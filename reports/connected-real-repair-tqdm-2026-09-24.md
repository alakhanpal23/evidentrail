# Exploratory connected-log repair probe on a real tqdm bug

This opt-in probe uses [BugsInPy](https://github.com/reproducing-research-projects/BugsInPy) `tqdm` bug 1. The buggy source revision is `8cc777fe8401a05d07f2c97e65d15e4460feab88`; the regression test and gold source come from fixed revision `c0dcf39b046d1b4ff6de14ac99ad9a1b10487512`. In an isolated Python 3.9 environment with pytest 5.4.3 and nose 1.3.7, the buggy source failed `test_enumerate` and the fixed source passed. The original benchmark records Python 3.6.9; this run uses a small compatibility alias for the removed `sys.setcheckinterval` method. The test still reproduced the same `TypeError` for a nonzero start value, but this is not the benchmark's original environment.

The reproduced failing-test output contained 173 lines and 8,074 bytes. An ignored connected-selector probe ingested every line as an exact record into an encrypted corpus and selected original lines under a 4,096-byte raw-log cap. It returned 12 lines and 795 bytes for both first-ID and Qwen2.5-Coder 7B selection, and 3 lines and 243 bytes for severity-only selection. The first-ID and model packs included the offending `return enumerate(tqdm_class(iterable, start, **tqdm_kwargs))` line; the severity-only pack did not. All selected bytes were verified against the encrypted source records. No candidate-pool or output-budget truncation was reported. On this one case, the model selected the same 12 lines as the simple baseline.

The repair reader received the task, the buggy `tqdm/contrib/__init__.py` source file, and one of those log packs or no logs. It could replace one unique source line per attempt. After each attempted edit, the evaluator ran the upstream regression test in a fresh copy; a failed attempt could use bounded test feedback for one more edit. The gold patch and test file were not shown to the reader. The harness independently checked that the buggy checkout failed and the fixed source passed before scoring.

| Repair reader | No logs | First-ID logs | Severity logs | Local-model logs |
| --- | ---: | ---: | ---: | ---: |
| Qwen2.5-Coder 7B, at most two edits | 0/1 | 0/1 | 0/1 | 0/1 |
| Qwen3 14B, at most two edits | 0/1 | 0/1 | 0/1 | 0/1 |

Every arm produced syntactically applicable edits on the second run, but none passed the regression test. The first 7B pass exposed an overly strict evaluator requirement that the reader reproduce indentation exactly; after a general unique-line matching fix, the same case was rerun. It is therefore **exploratory development data, not untouched held-out evidence**. The result demonstrates a real test-based failure despite retaining a useful traceback line. It does not establish whether a less constrained coding agent, different prompt, hosted model, or multiple repository-inspection steps would fix the issue, and it gives no evidence that Evidentrail improves repair success. More independently frozen issues with real execution and equal-budget baselines are required before routing or product-value claims.

To reproduce, check out the pinned buggy `tqdm` revision in a temporary directory and replace only `tqdm/tests/tests_contrib.py` with the fixed revision's regression test. Create a Python 3.9 virtual environment with `pytest==5.4.3`, `pluggy==0.13.1`, `py==1.8.1`, and `nose==1.3.7`; run the failing test and save its output. Set `EVIDENTRAIL_EXTERNAL_REPAIR_LOG`, `EVIDENTRAIL_EXTERNAL_REPAIR_OUTPUT_DIR`, `EVIDENTRAIL_EXTERNAL_REPAIR_TASK`, and `EVIDENTRAIL_COMPACT_LOCAL_MODEL`, then run `cargo test -p evidentrail-cli --lib external_repair_connected_selection_eval -- --ignored --nocapture`. Finally run `python3 scripts/eval-connected-bugsinpy-tqdm.py --repo CHECKOUT --python VENV/bin/python --selected-dir OUTPUT_DIR --model MODEL`. The script checks both buggy and fixed test outcomes and writes only contentless scores to stdout. Keep the repaired checkout and generated logs out of the repository.
