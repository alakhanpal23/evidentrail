# Cross-task route evaluation status — 2026-09-24

The route remains in shadow. No six-arm, independently verified held-out repair study exists in this checkout, so verified repair rate, model calls, latency, and cost for the learner are unmeasured. The promotion gate is closed. The older single-case tqdm repair probe and the synthetic retrieval suite do not qualify it.

The reproducible development replay is in [learning-route-shadow-2026-09-24.json](learning-route-shadow-2026-09-24.json). Run `python3 scripts/report-learning-shadow.py` from the repository root to regenerate it. Six frozen synthetic retrieval cases share a 4,096-byte raw-log budget per case. The current graph route found 7 of 7 labeled records and emitted 33 irrelevant logs. Lexical-only found 6 of 7 with 33 irrelevant logs; severity selection found 7 of 7 with 33; the recent-log baseline found 0 of 7 with 72. The Rust replay checks every arm’s selected bytes against the encrypted originals. This local run measured 21 deterministic selector invocations across six cases and the current-route p95 selection time shown in the JSON report; it made no hosted model calls. It does not measure downstream repairs or prove memory helps: the fixture has no independent training labels, so shadow memory has no effect.

A separate focused test exercises two independent source-local labels, a conflicting negative, an inactive shadow route, explicit promotion, and immediate fallback after label revocation. It is a mechanism test with synthetic records. The required learning ablation is `challenger` versus `challenger_no_memory` under the same frozen held-out tasks and budgets. `scripts/score-learning-route.py` reruns Prompt 1's verifier for all six arms and scores that ablation. A route needs both the Prompt 1 held-out repair gate and an independent memory-on benefit before `sources route promote` accepts it. No such result is present here.
